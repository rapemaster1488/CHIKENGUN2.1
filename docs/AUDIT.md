## 1. Что это за проект

FPS-арена на **Urho3D** (C++17), Linux/OpenGL. Собирается **одним файлом** `src/MyApp.cpp`:

| Компонент | Реализация |
|---|---|
| Движок | Urho3D (внешняя установка, `~/urho3d`) |
| Физика | самописная «Lite»: реестр AABB/сфер + рейкасты, Bullet **не используется** (намеренно) |
| Уровень | 192×192 м, пол 48×48 плит, стены, колонны, ящики, бочки, платформы, неон, вышки |
| Геймплей | режим «тир» (мишени) и «арена» (волны роботов: melee/charger/shooter/boss) |
| Оружие | 7 стволов (пистолет…гранатомёт), 8 скинов, перезарядка, ADS, отдача, разброс |
| UI | процедурный: главное меню с анимацией, настройки, арсенал (TAB), HUD, GAME OVER |
| Звук | WAV/OGG из `Data/Sounds`, музыка-луп, 3D-источник для взрывов |
| Прочее | загрузочный экран, hitmarker, виньетка низкого HP, трейсеры, осколки, комбо, рекорд в `settings.ini` |

«Технологичность» проекта примерно на уровне идеи, но **архитектурно это монолит**: один класс `MyApp : Application`, 4375 строк, 134 метода, ~120 полей состояния. Ни одного `#include` своего заголовка, ни одного теста, ни одной абстракции над вводом/рендером/UI.

## 4. Сборка и запуск

### 4.1 `build.sh` — что не так

| Место | Проблема | Последствие |
|---|---|---|
| Поиск заголовков | 3 кандидата + эвристики (`Core/UrhoVersion.h`, `Urho3D.h`, папка `Urho3D/`) | на другой машине нужен ручной `URHO_INC=...` |
| SDL | пытается создать симлинк `SDL -> SDL2` в системном `/usr/include` | без root не работает, лезет в системный каталог |
| Bullet | `$( [ -f lib.so ] || ls lib.so* && echo "-l..." )` | если `libBullet3Collision.so` **есть**, `-l`-флаги не добавляются вообще (короткое замыкание `||`) — работает случайно, за счёт `DT_NEEDED` у `libUrho3D` |
| После компиляции | `find build/Data ... -delete`, `find ~/urho3d/bin/... -iname '*.pfx' -delete` | **удаляет файлы из установки движка**, а не только из проекта |
| Ресурсы | `cp -rn` в `build/Data` при каждой сборке | дублирование, рассинхрон, «почему у меня старая текстура» |
| Нет `CMakeLists.txt` | сборка одной командой `g++` | нельзя добавить `-Wall -Wextra -fsanitize`, нет инкрементальной сборки, нет зависимости от `Urho3D` |
| `set -e` | но фоновые подсказки `|| true` | ошибки копирования проглатываются |

### 4.2 Игра в рантайме занимается файловой системой

`Start()` (строки ~660–790) до запуска игры:

- читает `/proc/self/exe`, ищет `Data`, `CoreData`, `TexturesHD`;
- `system("cp -r '...' '...'")` — копирует `CoreData`, `Fonts`, `Models`, `Textures`, `Materials/Game` в каталог бинарника;
- **(было)** `system("find '<path>' -iname '*.pfx' -delete")` — рекурсивно удаляла `.pfx` по путям, включая `~/urho3d/bin/Data`.

Последствия: (а) запуск игры может менять установку движка, (б) `system()` собирает строку из `exeDir` — если путь содержит кавычку/`;`, это инъекция команды (не критично для локальной игры, но паттерн плохой), (в) O(сотни) файловых операций на каждом старте, (г) логика «а если Data неполная» маскирует ошибки упаковки.

**Исправлено:** блок удаления `.pfx` убран полностью. Осталось копирование — рекомендую заменить на симлинк/преflight-проверку с понятным сообщением.

### 4.3 Запуск из README

```
cd bin && ./MyShooter
```

В `bin/` бинарника нет (он в `build/`), `build.sh` кладёт его в `build/MyShooter`, а `Data` ищется относительно бинарника. То есть README врёт: правильно `./build/MyShooter` из корня. Плюс `.gitignore` содержит `build/`, значит бинарника в репозитории и не будет. Это надо просто исправить в README (2 строки).

### 5.2 Что болит

| Проблема | Пример |
|---|---|
| Один класс — 4375 строк | любая правка = merge-конфликт в одном файле |
| Нет разделения UI/логики/рендера | `CreateHUD()` сам вызывает `UpdateAmmoDisplay()`, которая лезет в `weapon_` |

| Мёртвый код | `CreateCeiling()` — заглушка, `cache_GetSphere()`, `ToggleMouseVisibility()` (не привязан ни к одной клавише), `MakeProceduralParticles()` всегда возвращает пустой `SharedPtr`, `HandlePostUpdate` пустой, `ApplyGraphicsSettings()` частично «для галочки» |

## 8. Безопасность и надёжность

1. `system()` с конкатенацией путей (`cp -r '...'`): при кавычке в пути — инъекция; как минимум неэкранированные пути. **Рекомендую** заменить все `system("cp ...")` на `FileSystem::CopyDir` Urho3D.
2. Удаление файлов вне проекта (`.pfx`, `.mat`) — уже исправлено в коде, осталось в `build.sh`.
3. `settings.ini` парсится `atof` без проверки диапазона/валидности (частично исправлено) — стоит валидировать схему и писать атомарно (`.tmp` + `rename`), иначе выключение питания в момент записи = битый конфиг (и потерянный рекорд).
4. Нет обработки исключений/ошибок загрузки сцены: `LoadResources()` возвращает `true` даже если ни одна модель не нашлась (только warning'и) → игра стартует в «серую» сцену вместо понятной ошибки.
5. Рекорд и настройки — в одном файле; при порче `highScore_` теряется вместе с настройками. Разнести на `settings.ini` + `progress.ini`.
6. Секретов/токенов в репозитории не найдено (проверил `ghp_`, `github_pat_`, `AKIA…`, приватные ключи, `api_key`).

## 9. Геймплей и баланс (на что смотреть после фиксов)

- **Боезапас**: после того как переключение оружия перестало читерить, важен рефилл. Сейчас — полный резерв на каждой новой волне. Возможно, лучше +50 % за волну и/или пикапы патронов.
- **Сложность**: melee 10 урона/1 с, charger 20/1.5 с, boss 30/1.2 с при 100 HP игрока; на 3-й волне одновременно до 6 роботов, часть из них стреляет. Аптечек нет вообще — только рестарт. Стоит добавить регенерацию или аптечки.
- **Комбо** даёт `base * (1 + 0.5*(combo-1))` — на 10 убийствах множитель ×5.5; очки быстро улетают, рекорд обесценивается. Ограничить множитель (например, ×3).
- **Награда за точность**: `spreadAngle = spread * (1 - accuracy/200)` — при 100 % точности разброс падает вдвое; это скрытая механика, её никто не видит, и она «награждает» уже точных игроков.
- **ADS**: FOV −25°, скорость −40 %, разброс ×0.35 — сильно; но оружие при ADS не «прилипает» к центру (`WeaponBasePose` возвращает 0,-0.16,0.45, прицела нет).
- **Скины** дают emissive-цвет, но `SetShaderParameter("MatDiffColor")` на unlit-материале; работает, но bloom есть только при `gfxGlowIdx_==2` — половина смысла скинов пропадает при настройке «слабый».
